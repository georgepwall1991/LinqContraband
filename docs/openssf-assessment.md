# OpenSSF Best Practices assessment

This is a draft assessment, not an earned badge or a submitted self-certification. It covers all 67 passing-level criteria, checked on 2026-10-05 against the [official requirements](https://www.bestpractices.dev/en/criteria/0). The base source snapshot is `faf8429d49afe581d3e984975cabb520dc23589e`; documentation changes in this assessment must be merged before their URLs serve as public evidence.

Prepared answers: **59 Met, 7 N/A, 1 Unmet**. The unmet item is suggested. George Wall confirmed the developer-knowledge declarations on 2026-10-05. Do not claim an earned badge until enrollment and submission are complete and the OpenSSF service reports passing.

The [JSON draft](openssf-assessment.json) contains proposed project identity, criterion statuses, justifications and evidence URLs. No project badge ID is present because enrollment has not occurred.

## Remaining human and account dependencies

- Sign in to [OpenSSF Best Practices](https://www.bestpractices.dev/en/projects/new) with the maintainer GitHub account; register this repository after confirming no existing enrollment.
- The developer-knowledge declarations are confirmed. The [secure-development guide](https://georgepwall1991.github.io/LinqContraband/secure-development.html) records the principles and mitigations.
- Owner George Wall will provide human reviews for contributions by other authors. GitHub prevents his account from approving PRs authored by that same account. Keep the current PR/CI gate while only that account has access; an AI review cannot establish independent human review history.

## Verification snapshot

- 5,950 net10.0 tests passed: 90.96% line coverage, **78.53% branch coverage**. Do not confuse line coverage with the badge's alternative 80% branch-coverage route for dynamic analysis; the FsCheck properties provide the variable-input route.
- All 17 public non-PR issues were closed or responded to; creation dates fall in the current 2-12 month reporting window.
- No project advisories, package advisory-database matches, Dependabot alerts, or secret-scanning alerts were returned by the relevant admin APIs. These snapshots do not guarantee absence of every vulnerability.
- Private vulnerability reporting, Dependabot alerts and automatic security updates, secret scanning and push protection are enabled and were read back.
- The optional strict analyzer-enabled build reports 143 pre-existing errors. It is disclosed as an unmet suggested strict-warning criterion rather than hidden by weakening checks.
